# GradTrack — Definition of Done

A User Story is considered **Done** only when:

- [ ] All acceptance criteria are satisfied.
- [ ] The feature is implemented and works as expected.
- [ ] Relevant unit and integration tests pass.
- [ ] Gherkin scenarios pass when applicable.
- [ ] Code follows the agreed coding standards and passes linting.
- [ ] The feature is reviewed by another team member.
- [ ] The Pull Request is merged and CI passes.
- [ ] Relevant documentation is updated.
- [ ] The feature is demonstrated and accepted by the Product Owner during the Sprint Review.

**Additional Rules:**

- Backend permissions and business rules must be tested.
- No critical bugs or security issues remain unresolved.
- No real student data, secrets, or credentials are committed.
- An unfinished or untested feature cannot be marked Done.
